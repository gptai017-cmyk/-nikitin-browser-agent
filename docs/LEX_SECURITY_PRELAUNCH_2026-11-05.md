# ЛЕКС → Безопасность: предварительный набор, 05.11.2026

## Границы релиза

- Существующие 34 DOCX/ZIP, MAX/Telegram webhook, платёжная интеграция и страхование **не меняются**.
- В главном меню Лекса добавляется «Безопасность» (подзаголовок «Семья, дом и имущество»), разделы: «Защитить квартиру / дом», «Безопасность бизнеса» (только информация), «Страхование» (переход в действующий `/store/partners`), «Что делать при ЧП» (инструкция обращаться 112, **не** кнопка SOS).
- Пенза: концепция «ПРАЙД 500», ориентир ~499 ₽/мес. — **не утверждённый тариф**, без запуска ГБР, оплаты, рекуррентных списаний или постановки на охрану. Другие города: только предварительный запрос на подбор будущих партнёров.
- Публичные страницы `/security`, `/security/home`, `/security/business`, `/security/emergency`, `/security/consent`. Источник из ссылки `source` (LEX/MAX/TELEGRAM/DIRECT/PARTNER/OTHER). Источник по query-string является **заявленным, не криптографически подтверждённым**; это атрибуция маркетинга, не доказательство сделки.
- Административная страница `/security/admin`, API `/security/api/admin/leads`. Фильтры city/status/product/date, выдача до 50 записей за запрос. Секрет администратора не публикуется, не записывается в localStorage, снаружи не выдаётся без проверки.
- Отдельный чекбокс согласия с текстом `/security/consent` и актуальной политикой `/store/privacy`. До активации подача реальных персональных данных блокируется.
- Автоматической передачи третьим лицам, новых партнёрских ссылок, CRM, финансового учёта, dispatch и кнопки вызова охраны нет.

## Данные и статусы

`security-intake-ru/schema.sql` содержит таблицу `security_leads`:

| Колонка | Назначение |
|---|---|
| lead_id | UUID, серверный ID |
| created_at | момент регистрации ISO 8601 UTC |
| source | LEX / MAX / TELEGRAM / DIRECT / PARTNER / OTHER |
| city | город |
| district_or_address | район, без необходимости точного адреса |
| object_type | APARTMENT / HOUSE / BUSINESS |
| family_members | целое 1–30 для Пензы, иначе null |
| name | имя заявителя |
| phone | контактный телефон |
| comment | необязательный текст |
| product | PRIDE_500_PRELAUNCH / SECURITY_PARTNER_SEARCH |
| partner | пока всегда null |
| referral_source | необязательная будущая атрибуция |
| status | первоначально NEW |
| consent_version / consented_at | отдельная история факта согласия |
| expires_at | крайний срок 180 дней с регистрации |

Допустимые статусы: **NEW, CONFIRMED, WAITING_LAUNCH, SENT_TO_PARTNER, CONTRACT, CONNECTED, ACTIVE, DECLINED**. В этой итерации создаётся только NEW; остальное — словарь будущей маршрутизации, нельзя автоматически интерпретировать CONNECTED или ACTIVE как реально подключённую охрану.

Индексы: city/status, product/created_at, created_at. Нет паспортных данных, карт, фотографий, геолокации, геокоординат, реквизитов собственности. Сообщения не пересылаются ЧОО автоматически.

## Условия законного включения (в текущем production выключено)

С 01.07.2025 ст. 18 ч. 5 152-ФЗ запрещает при обычном сборе ПД граждан РФ первичное хранение/запись/систематизацию в базе за пределами России (за исключениями, перечисленными в норме). Cloudflare KV/D1/Durable Objects в текущей конфигурации не подтверждены как российские хранилища. **Нельзя включать приём реальных телефонов/адресов туда.**

Создан автономный минимальный адаптер `security-intake-ru/server.py` + `schema.sql` для российской инфраструктуры. Он запускается только при `SECURITY_RU_HOST_ATTESTED=true`, слушает `127.0.0.1`, использует SQLite с локальным файлом и авторизацию секретом. Развертывание в проверенном российском ДЦ, TLS-терминация, WAF/rate limits, шифрование диска, backups в РФ и режим доступа ещё НЕ выполнены. Не выставлять этот порт напрямую в интернет и не использовать его в продакшене без проверки.

Перед включением необходимо:
1. Определить **юридически корректного оператора** ПД (за кем ответственность, реквизиты, контакт, уведомление РКН при необходимости) и убедиться, что он указан на странице отдельного согласия.
2. Арендовать подтверждённый российский сервер/диск/резервные копии, настроить HTTPS endpoint `/v1/leads` и `/v1/leads?city&status&product&date` с авторизацией. Проверить, что инфраструктура не логирует содержимое POST, что backend не раскрывает записи без ключа; шифровать диск и резервные копии.
3. Провести правовую оценку того, что Cloudflare Worker выступает транзитным прокси: проверка иностранной обработки, иностранных технических логов, допустимости транзита, правовых оснований и договоров. При необходимости направить PII напрямую на российский origin, чтобы не проходить через иностранный Worker; нельзя считать форму соответствующей только потому, что конечная БД находится в РФ.
4. Согласовать retention 180 дней, удаление по отзыву и регламент уведомления о нарушениях; протестировать восстановление, отказоустойчивость и разграничение доступа.
5. Подключить секреты/переменные **только к MAX Worker** (не в GitHub, не в HTML):
   - `SECURITY_INTAKE_ENABLED=true` — последний, после проверок;
   - `SECURITY_RU_STORAGE_CONFIRMED=true` — только с проверенными документами о российской базе;
   - `SECURITY_RU_API_BASE=https://...` — российский защищённый сервер;
   - `SECURITY_RU_API_KEY` — длинный случайный секрет, отдельный от токена MAX/TG;
   - `SECURITY_ADMIN_TOKEN` — отдельный длинный случайный секрет для просмотра;
   - `SECURITY_PD_OPERATOR_NAME` — правдивое имя/наименование оператора;
   - `SECURITY_PD_OPERATOR_CONTACT` — действующий контакт оператора.
6. Повторить живой тест двух вымышленных заявок, проверить их фактическое сохранение в **российской** базе и появление в админ-списке, затем очистить тестовые записи. Настроить мониторинг отказов без утечки персональных данных. Лишь после этого можно заявить DONE по сбору заявок.

**Текущее состояние:** интерфейс виден, кнопка отправки при отсутствии конфигурации отключена, POST отвечает HTTP 503 **до парсинга пользовательских данных**. Тесты synthetic/mock подтверждают разработку, но не заменяют реальное сохранение на российском сервере. Это ожидаемая защита, а не дефект.

## Реклама и охранное право

- Telegram-бот содержит информационный вход, но целевую рекламу, рекламные рассылки и массовые публикации охранной услуги в Telegram **не включать**. ФАС 25.03.2026 объяснила переходный период по ответственности за рекламу в Telegram до 31.12.2026; это не является разрешением на любую рекламу.
- MAX — основная предполагаемая площадка продвижения; **пока только функциональный раздел без платной кампании**. Перед платной рекламой изучить 38-ФЗ, маркировку, юридическую роль рекламодателя и требования к охранной услуге. Нельзя рекламировать уже действующую защиту, если она не действует.
- С 01.09.2026 вступил в силу 427-ФЗ о частной охранной деятельности. Партнёрская ЧОО, её лицензия, реальная зона выезда, количество ГБР и договор будут согласованы отдельно. НПД и будущие агентские комиссии требуют отдельного налогового решения.

## Следующая итерация — только план, не выполнять автоматически

- Обеспечение российского хранения и правовых документов (блокер до реального приёма);
- Проверка и подписание согласованной модели с ЧОО «Прайд», тарифа, маршрута реагирования, учёта расходов и ответственности;
- Подключение ручной передачи/реферальной ссылки в других городах только после письменного согласия конкретного заявителя, договоров с партнёрами и налоговой проверки;
- Полноценная административная роль с 2FA, изменение статуса, аудит доступа, предупреждения о старении заявок;
- Только затем — фактический охранный сервис, ГБР и отдельно проверенный биллинг. Сейчас всё это запрещено флагами.

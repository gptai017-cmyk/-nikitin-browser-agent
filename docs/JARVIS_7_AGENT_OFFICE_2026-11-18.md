## Техническая модель

**Один оркестратор** (ДЖАРВИС) принимает голосовое или текстовое поручение, назначает одну ведущую роль, формирует контрольный результат, при необходимости последовательно привлекает другие роли и фиксирует итог в Wrike. Это не семь Telegram-ботов и не семь постоянно работающих моделей.

Реализован только безопасный первый слой: `worker/src/office-agents.js` — каталог ролей и маршрутизатор без внешних вызовов. Тесты: `test/office-agents.test.js`. Подключения и автономные действия кода **не реализованы этим PR**.

## Этапы

1. Проверить уже существующий production: /health, голосовой запрос, /report, /voice. В текущей реализации прямые Gmail/Wrike API и синтез речи требуют отдельных Cloudflare Secrets; GitHub merge не доказывает готовность.
2. Добавить в owner-only Telegram явную команду /office с выбором специализации, сохранением инициативы/ошибок в контролируемом журнале и без дублей. Для безопасных операций разрешить черновики, для внешних изменений — confirmation gate.
3. Подключить модели для исполнения ролей и структурированный обмен результатами между ролями. Использовать облачный лимит, тайм-ауты, изоляцию контекста и запрет передачи лишних персональных данных.
4. Протестировать 3 сквозных кейса: «поручение о сайте ЛЕКС», «исследовать нишу ЕЦЦУ», «подготовить рекламные объявления без публикации». Проверить, что результат реально появился в исходной системе.
5. Только после проверки упаковывать как платную услугу ЕЦЦУ (разовое внедрение + сопровождение).

## Безопасность

- Владелец остаётся единственным утверждающим финансовые операции, внешние отправки, публикации, доступ к персональным данным и production-деплой.
- Никаких токенов и секретов в публичном репозитории, сообщениях Telegram и описаниях задач.
- Из Cloudflare Worker — минимальные доступы, желательно read-only, до отдельного этапа согласованных записей.
- Личные судебные материалы, медицинские сведения, паспортные данные и другие чувствительные документы не импортировать в общий контекст.
- Не считать «задача создана» равнозначным «действие выполнено». В каждом поручении нужен проверяемый результат.
- 24/7 зависит от стабильности платформ, мониторинга и лимитов, работа API/хостинга не бесплатна.

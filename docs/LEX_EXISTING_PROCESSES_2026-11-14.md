## Стандарт выполнения внешних действий

1. Сначала найти существующие файлы/секреты/рабочий канал и проверить живое состояние. **Не предлагать Work или TinyFish как обязательную предпосылку**.
2. Для внешнего сайта использовать Telegram Browser Agent. Из ChatGPT — его уже существующий шифрованный маршрут через GitHub Issue и Actions, если доступны необходимые инструменты; в случае отказа зафиксировать точную техническую причину. Не обходить криптографическую авторизацию.
3. Для доступа к аккаунту использовать сохранённую браузерную сессию только соответствующего профиля/сайта. Личные данные брать из доверенного контекста текущей задачи. Не хранить PIN, OTP, паспортные данные, токены или пароли в публичных артефактах.
4. При SMS/CAPTCHA/банковском подтверждении останавливать агент и давать владельцу выполнить требуемый шаг безопасно. Не объявлять операцию совершённой до подтверждения на экране и readback.
5. Не раскрывать поставщикам внутреннее устройство и стратегию ЛЕКС/REACTA, тарифные конструкции, комиссии, планы запуска и реферальную архитектуру. Запрашивать только условия продукта.
6. После каждого шага сообщать **факт**: проверено / выполнено / ошибка / нужен ввод владельца. Не путать «код подготовлен», «workflow запущен» и «регистрация подтверждена».
7. При изменениях ЛЕКС проверять регрессию документов, страхования, безопасности, рефералов, Telegram и MAX. Не включать реальные SOS/ПЦН/платежи автоматически.

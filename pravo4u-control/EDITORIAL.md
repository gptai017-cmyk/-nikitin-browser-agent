# Редакционный стандарт ПРАВО4U × Земельный банк

Дата старта: 10.10.2026. Управление: ChatGPT → GitHub (ветка `pravo4u-control-integration-20261010`) → GitHub Actions → @advokat4ubot. Только публичные @pravo4urus и @zemlibank. Бот основного ПРАВО4U и его webhook не изменять.

## Продуктовые обещания
Мы не продаём новости. Мы уменьшаем неопределённость и стоимость ошибок.
- **ПРАВО4U**: обычному человеку понятен конкретный следующий шаг в юридической ситуации; простые документы в Лексе, платные конструкторы и лиды юристам при рисках.
- **Земельный банк**: покупателю/владельцу/инвестору понятны правовой режим, экономика участка и практическая проверка. Перевод в договорную часть через Лекса — только где документ реально доступен.

## Неизменные стандарты
1. Реальная потребность человека в первой строке: конкретная ситуация, риск, последствие. 1 пост — 1 проблема — 1 решение.
2. Практический порядок действий в пределах 500–1400 знаков; короткие абзацы, доступный русский. Не перегружать эмодзи и не создавать пустой искусственный ажиотаж.
3. Юридические утверждения сверять с первичными нормами на дату публикации, серьёзные факты — минимум с одним авторитетным источником. Источник обозначать в публикации. Не выдавать персональные правовые заключения, результаты не гарантировать.
4. Факт о конкретном участке/сделке/цене — только при подтверждённых документах и разрешении на раскрытие. Не публиковать сведения сторон, точные кадастровые номера клиентов, финансовые и медицинские данные.
5. Заключение: одно действие читателя: сохранить, переслать или использовать нужную функцию Лекса. Продажа в каждом посте запрещена; ориентир не более 20% рекламно-продуктового контента.
6. Не обещать действующие цены Stars, наличие функций, компенсацию или юридический эффект, пока не проверены production и нормативная база.
7. Не спамить комментариями/личными сообщениями, не накручивать подписчиков, не покупать ботов, не использовать сомнительные взаимопиары.
8. Перед каждой публикацией проверять уже опубликованные темы, время последнего поста, цель и смысл. Ритм до роста аудитории: максимум один содержательный пост в день на канал (не обязателен при отсутствии ценного материала).
9. Никаких неанонсированных изменений основного webhook, production, платежей, бота, секрета, основной ветки `main`.
10. Каждую публикацию проверять по GitHub Actions. `success` без строки `SUCCESS ... message_id ...` не подтверждает размещение. При `uncertain` не отправлять повторно, сначала сверить фактическое состояние.

## Рубрики
**ПРАВО4U:** 40% «Ситуация → что сделать»; 25% «Ошибка и цена ошибки»; 20% «Документ за 5 шагов»; 15% «Проверенная новость и последствия». Ключевые темы: судебные приказы, приставы, недвижимость, ИП, договоры, наследство; военные вопросы — осторожно, родственники как отдельная аудитория, без обещаний исхода.
**Земельный банк:** 30% «Проверка до сделки»; 25% «Что в документах»; 20% «Экономика земли на расчётах»; 15% «Разбор инфраструктуры/девелопмента»; 10% «Проверенные новости рынка». Термины объяснять, не использовать не подтверждённую доходность.

## Рост и дистрибуция
**Стадия 0–100:** узнаваемые посты, полезные чек-листы, релевантные перепосты добровольных партнёров, профили в поиске Telegram, корректные ссылки с собственных ресурсов. 1–2 качественных гипотезы распространения в неделю; цель — не искусственный прирост, а заинтересованные подписчики.
**Стадия 100–500:** совместные разборы с кадастровыми инженерами/юристами, аккуратные тематические подборки, воронки с помеченными источниками и измерением конверсий, первые платные тесты только после экономического расчёта.
**Стадия 500+:** партнёрские рекомендации и продукты, платные документы и лидогенерация, реклама только при достоверных показателях охватов и соответствии тематике.

## Ежедневные показатели
- Подписчики по обоим каналам и прирост к предыдущему замеру (Bot API `getChatMemberCount`).
- Фактически опубликованные посты и ссылки на сообщения.
- Просмотры/реакции/репосты — только если есть достоверный доступ к Telegram UI/статистике. Bot API сам по себе **не предоставляет** точный счётчик просмотров постов; не выдавать подписчиков за охват.
- Клики и лиды — только после атрибуции deep links/бот-логов, без придумывания.
- Расходы на дистрибуцию, доходы от документов/партнёров, чистая экономика по каждому источнику.

## Правило исполнения из ChatGPT
Выбирать уникальный UUID; создавать отдельный файл `pravo4u-control/commands/<uuid>.json` в изолированной ветке с `operation`, `channel`, `text`, `dry_run:false`. Прочитать GH Actions run, проверить успешный статус и подтверждение `SUCCESS ... message_id`. Для диагностики можно создавать `verify` или `inspect` с `dry_run:false`: они ничего не публикуют. Токен всегда берётся из GitHub Actions secret `PRAVO4U_BOT_TOKEN` и нигде не копируется.

# REACTA / ЛЕКС в MAX — MyAlarm и резервный SOS. Протокол допуска к запуску
Дата: 11.11.2026. Статус: подготовка. НЕТ действующего вызова ГБР через MAX.

## Решение по продукту
- Основной интерфейс охраны — готовое приложение ЧОО: MyAlarm при работе с ПО «Центр Охраны» Си-Норда или иная платформа, согласованная с конкретным ЧОО.
- ЛЕКС/MAX — маркетинг, доступ к инструкциям, заявки на подключение и далее отдельный **резервный** канал тревоги (после проверок).
- MyAlarm КТС формирует событие по **закреплённому объекту**, а не по GPS телефона. Нельзя рекламировать как персональный GPS SOS.
- В MAX сейчас сценарий «КТС не сработала» только инструктирует звонить дежурному ЧОО по номеру договора и в 112 при угрозе жизни. **Не отправляет тревогу, не просит телефон, адрес, геолокацию, не утверждает, что ГБР вызвана.**

## Юридическая модель «как диспетчеризация такси»
ФЗ № 427-ФЗ вступил в силу 01.09.2026. Статья 8 предусматривает охранные договоры ЧОО с заказчиком и соисполнителем/субподрядчиком. Клиент заключает договор с ОСНОВНОЙ лицензированной ЧОО, которая отвечает перед клиентом, а другие лицензированные ЧОО получают задания по межоператорским договорам (на законных условиях объекта). REACTA не выступает сама как охранная организация и не продаёт собственные охранные услуги без лицензии.

- Договор клиент ↔ основное ЧОО с описанием субподрядчиков и механизмов реагирования.
- Договор основная ЧОО ↔ каждое ЧОО-соисполнитель; лицензия, зона, согласованные основания доступа, ответственность, SLA, акты выездов.
- Договор REACTA ↔ основная ЧОО: доступ к SaaS, учёт заявок/платежей, интеграции, вознаграждение.
- Согласие на обработку/передачу необходимых клиентских данных по применимым основаниям; проверенное российское хранение.
- Трудовые/договорные основания для обработки геолокации экипажей во время смены.
- Правила подтверждения выезда и перераспределения, страховка ответственности и журнал разбора претензий.

## Будущий рабочий резервный вызов (отдельно)
1. Клиент ранее подписал договор с ЧОО. MAX ID и разрешённые объекты привязаны через защищённую процедуру на российском backend с верификацией личности; нельзя принимать объект «со слов из чата».
2. Пользователь выбирает «Резервный SOS», подтверждает конкретный объект и обращение. Для объектовой КТС координаты телефона не требуются.
3. MAX webhook передает только безопасное командное событие; идентификация и обработка личных данных в российском контуре. Запрет проксирования ПДн через Cloudflare без отдельной правовой и технической проверки.
4. Плагин конкретной ЧОО направляет **идемпотентное, подписанное** сообщение в подтверждённый канал ПЦН; проверяет доставку и статус принятия **оператором**, а не только HTTP 200.
5. Только после подтверждения ПЦН пользователь видит «Тревога принята дежурной частью» и номер инцидента. Отдельно — подтверждённый статус назначения ГБР. Нет подтверждения — явно «Не подтверждён вызов. Позвоните дежурному/112».
6. Таймауты, повторная доставка, защита от повторного вызова, журнал инцидента, тесты восстановления соединения, эскалация оператору и резервная голосовая связь обязательны.
7. Переадресация субподрядчику только если лицензия, зона и договор действуют; назначение подтверждено ПЦН и экипажем; не «случайная ближайшая машина».
8. Тестовые тревоги отдельной среды, проверка при потере интернета, тест двойного сигнала MyAlarm/MAX, отказ связи, отсутствие дублирования ГБР, письменное согласование ЧОО.

## Финансовая модель без мультидоговора клиента
- Абонент платит основной ЧОО; договорный провайдер получает выручку за услугу, REACTA — вознаграждение за SaaS/привлечение по контракту.
- ЧОО-субподрядчик выставляет основной ЧОО плату за подтверждённый выезд. Не платим «ближайшему» за статус GPS без факта выполнения.
- Резерв на реагирование и экономику ложных вызовов считаем по фактической частоте/себестоимости, прежде чем обещать безлимит за 500 ₽.
- Не меняем утверждённые доли платёжной системы REACTA без согласования владельца.

## Условия разблокировки реального SOS
- [ ] Определить ПО ПЦН, версию, API и контакты дежурной части ПРАЙД (подтвердить фактически).
- [ ] Договоры/правила субподрядчиков и ответственность согласованы.
- [ ] Российский сервер, хранение, безопасность, мониторинг и отказоустойчивость проверены.
- [ ] Механизм идентификации заказчика и привязки объекта испытан.
- [ ] API-адаптер ПЦН принимает/подтверждает тревоги в тестах.
- [ ] Учтены PII/152-ФЗ, права сотрудников на геолокацию.
- [ ] Нагрузочные/аварийные испытания и инструкция операторов подписаны.
- [ ] Чётко определены SLA/точки эскалации и резервный телефон, протестированы 24/7.
- [ ] Отдельное решение владельца на активацию production SOS.

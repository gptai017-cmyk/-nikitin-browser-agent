# ПРАВО4U — безопасная приёмка платежей Robokassa (27.10.2026)

Статус: магазин ПРАВО4U активен в Robokassa (подтверждено скриншотом владельца). Это НЕ означает, что покупка через конструктор уже запущена. Ни одна реальная оплата из этого репозитория не подтверждена.

## Настройки в личном кабинете Robokassa

Для существующего магазина ПРАВО4U, НЕ создавать новый:

- Алгоритм подписи: **SHA256** как для рабочего, так и для тестового режима.
- Result URL: `https://pravo4u-max.cbd-legal-cloudflare-worker.workers.dev/api/pay/result`, **POST**.
- Success URL: `https://pravo4u-max.cbd-legal-cloudflare-worker.workers.dev/pay/success`, **GET**.
- Fail URL: `https://pravo4u-max.cbd-legal-cloudflare-worker.workers.dev/pay/fail`, **GET**.
- Сохранить `MerchantLogin`. Это идентификатор магазина в технических настройках, не имя владельца.
- Создать отдельные **тестовые** пароль №1 и пароль №2. Никому не пересылать; не помещать в GitHub-файлы или в чат.
- Для НПД в разделе фискализации включить **«Робочеки СМЗ»/«Самозанятые ФНС»**, выдать партнёру Robokassa разрешение в приложении **«Мой налог»**; дождаться подтверждения состояния «Активно». Наличие активного магазина не равно активности формирования чеков.

## Изолированный Cloudflare Worker `pravo4u-max`

В настройках **этого** Worker -> Variables and Secrets -> Secret:

| Переменная | Значение | Режим |
| --- | --- | --- |
| `ROBO_MERCHANT_LOGIN` | точный `MerchantLogin` в кабинете | оба |
| `ROBO_TEST_PASSWORD_1` | тестовый пароль #1 | тест |
| `ROBO_TEST_PASSWORD_2` | тестовый пароль #2 | тест |
| `ROBO_PASSWORD_1` | рабочий пароль #1 | реальный |
| `ROBO_PASSWORD_2` | рабочий пароль #2 | реальный |

Обе пары — исключительно Cloudflare Secrets. Если значение уже есть, не публиковать и не перезаписывать без проверки.

Тестовые переключатели: `ROBO_TEST_ENABLED=true`, `ROBO_LIVE_ENABLED=false`, `ROBO_NPD_CHECKS_ENABLED=false`.
Боевые переключатели (только после успешного sandbox E2E и фискальной приёмки): `ROBO_TEST_ENABLED=false`, `ROBO_LIVE_ENABLED=true`, `ROBO_NPD_CHECKS_ENABLED=true`.
Два режима нельзя включать одновременно. Заказы в разных режимах изолированы по именам Durable Object. Переключение проделывать только при проверенном результате тестовой оплаты и выдачи документа.

Публичная проверка режима без ключей: `GET /api/pay/config`. Возвращает `mode: "free" | "test" | "live"`, `ready` и `priceRub`.
Во время теста `GET /compose?type=order` должен показать «Тестовая оплата 50 ₽ — без списания». Робокасса получает `IsTest=1`, отдельные тестовые пароли. Не повторять платёж при неподтверждённом статусе без проверки заказа.

## Контрольный E2E: реальный провайдер, тестовый режим, без списания

1. Открыть `/compose?type=order`, принять оферту, выбрать тестовую оплату.
2. Убедиться в `IsTest=1`, пройти тестовый платёж через интерфейс Robokassa.
3. Проверить подлинный серверный POST Robokassa на ResultURL с подписью тестового пароля #2, ответ `OK<InvId>`.
4. Вернуться по SuccessURL, нажать «Проверить оплату»; заполнить синтетическую анкету и скачать DOCX.
5. Открыть DOCX и проверить текст, формат, затем отказоустойчивость: неверная сумма, неверная подпись, чужой `claim`, повторный callback, второй неоплаченный заказ.
6. Только после успешной выдачи тестового DOCX, согласования условий оферты и подтверждения регистрации чека НПД — переходить к боевому режиму. Отдельно проверить первый реальный платёж минимальной согласованной суммы и сформированный чек ФНС.

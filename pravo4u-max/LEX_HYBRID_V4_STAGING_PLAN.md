# ЛЕКС — реализация Hybrid 4.0 (изолированная разработка)

Дата старта: 2026-11-12. Статус: стадия подготовки; НЕ в production.

## Принятое решение
- Не создавать третий независимый сайт через «Сайты».
- Существующий проект Cloudflare Worker / GitHub остаётся единственным источником документов и услуг.
- Публичный сайт: выразительный Premium Tech, навигация Главная / Документы / Страхование / Охрана / Услуги.
- MAX: Precision Luxury, четыре вкладки Главная / Документы / Защита / Услуги; внутри «Защиты» страхование и охрана.
- Все 34 существующих конструктора, генераторы DOCX, правила бесплатности и каналы оплаты сохраняются.
- Сторонние предложения страховки отображаются как предложения к оформлению лишь после подтверждённого рекламного соответствия и доступности оффера.
- Охрана не может подтверждать вызов ГБР до работающей интеграции с ПЦН; не показывать MyAlarm как продукт ЛЕКС.
- Референсы: Linear — визуальная дисциплина, Stripe — формы/состояния, Raycast — поиск, Rocket Lawyer — последовательность документа, Т-Банк — понятность страхования.
- Прототип: /mnt/data/lex_hybrid/LEX_Hybrid_PremiumTech_PrecisionLuxury.html в текущем рабочем окружении (локальный арт-дирекшн, не серверный артефакт GitHub). Не считать демонстрационные анкеты юридически готовыми документами.

## Текущее техническое состояние
- Production Worker: pravo4u-max.cbd-legal-cloudflare-worker.workers.dev
- Конфигурация wrangler.jsonc содержит `preview_urls: false`.
- Workflow .github/workflows/deploy-pravo4u-max.yml деплоит на каждый push в main (а не на feature-ветки).
- Следовательно, нельзя публиковать UX-эксперименты в main без отдельной приёмки.
- Feature-ветка: lex-hybrid-v4-staging; изменения отсюда не деплоятся автоматически.

## План поставки
1. Восстановить из утверждённого HTML-прототипа оригинальную design system (токены света/цвета, текст, сетка, навигация, focus/hover/active), устранить «концептуальные» заглушки.
2. Сделать изолированный preview: отдельный Worker/Pages или конфигурация тестового окружения БЕЗ связки с production Durable Objects, платежами, MAX webhook, тревогами, персональными данными. Использовать штатный механизм деплоя после аудита секретов и bind.
3. Подключить реально существующие маршруты 34 документов к единой системе поиска и глубокой навигации.
4. Завершить end-to-end путь ДКП земельного участка: реальная анкета → валидация → документ → скачивание; не заменять старый юридически проверенный генератор демонстрацией.
5. Проверить сайт и MAX отдельно: сайт — самостоятельные страхование/охрана; MAX — общая «Защита».
6. Тесты: 34 DOCX, без изменения условий оплаты, нет доступа к личным данным на Cloudflare, не пропадают заказы/бот, запреты на фиктивное страхование/SOS.
7. Проверка на iPhone Safari/MAX WebView, Android, десктопе: полный путь от поиска до DOCX, клавиатура, back, ошибки, touch targets, визуальные состояния.
8. Презентация пользователю на тестовом URL. Production-merge строго после явного утверждения.

## Приемка первой версии
- Ничего не сломано в production.
- Нет неизвестных пользователю промежуточных браузерных переходов.
- В действующем рабочем конструкторе получаются настоящие DOCX, а не fake preview.
- Минимальная навигация не отвлекает от задачи.
- Нет повторной шапки MAX.
- Карточки не создают «пустых» кликов и не рекламируют неактивные направления как оформляемые.
- Доступность: мобильный минимум 320px, WCAG AA по контрасту и клавиатуре, понятная ошибка для любого действия.

## Что требуется от пользователя
Сейчас — ничего. После появления preview — открыть на iPhone и оценить. Перед запуском возможны: собственный домен, утверждение юридической информации, реквизиты реферального партнёра (не блокируют работу UX).
